# KStruct — Revit 2024

KStruct targets .NET Framework 4.8, WPF, x64, and Revit 2024. In Revit, use `KStruct > COLUMN REBAR V3 > Tạo bộ bản vẽ thép cột` after generating KStruct V3 Rebar and saving deployment settings; select columns first or pick them when prompted. This command documents existing KStruct V3 reinforcement and does not create missing bars. Column bar counts/types, tie layout, starter lengths, and footing-anchor lengths must come from an identified approved design; missing values are left blank and require user entry/confirmation. Generated sheets and viewport titles are marked `DRAFT` and do not certify design approval. Inter-storey lap splices, staggered splices, and section transitions are rejected rather than inferred or generated.

The native `Ký hiệu đầu thép` command now defaults to a family-free KStruct annotation: it creates a filled/detail circle and a `Ø` diameter TextNote at the nearest unhooked Rebar end. A loaded View Based Detail Item with a writable `DK` parameter remains available as an optional compatibility mode; the native mode requires no BimSpeed family asset.

The native `Nhập tham số Excel/CSV` command pairs with `Xuất dữ liệu Excel/CSV`: it reads the first worksheet in `.xlsx` or a UTF-8 CSV, resolves rows by UniqueId, updates the Mark and matching `Parameter: <name>` columns after a preview and confirmation, and skips missing, read-only, blank, or invalid values. Export writes a native `.xlsx` workbook or UTF-8 CSV with ElementId and UniqueId columns. ElementId-only matching is supported for older CSV files only when they lack UniqueId. Parameters whose names are duplicated on one element need a dedicated mapping workflow.

The native `Lập hồ sơ cốt thép sàn` command creates a sheet per selected horizontal Floor with a cropped floor plan and two perpendicular sections, using Revit views and the existing model Rebar. It requires a Floor Level and a loaded Title Block; template-specific annotation and sheet layout remain subject to review in the project.

The native straight-beam reinforcement now supports uniform stirrup spacing or separate maximum spacing in both end zones and the middle zone. End-zone length and the three spacing settings persist per project and are optional Excel/CSV columns, so older beam configuration files retain uniform spacing.

Straight-beam reinforcement now also lets the top and bottom primary rows use different RebarBarTypes, counts, and bar diameters. The Excel/CSV `TopTypeName` and `BottomTypeName` columns are optional; without them, both rows continue to use the legacy `MainTypeName`.

Straight-beam reinforcement supports independent start/end `RebarHookType` selections for the top and bottom primary rows. The second row on each side inherits that side's hooks. Excel/CSV may specify `TopStartHookTypeName`, `TopEndHookTypeName`, `BottomStartHookTypeName`, and `BottomEndHookTypeName`; blank values leave the bar ends unhooked.

The native `Cốt thép dầm theo trục` command accepts straight grids or straight structural beams as axis sources, finds parallel straight beams on the active/source level, and applies the same KStruct beam-reinforcement settings to the matched run. It uses a 250 mm axis-distance tolerance and rejects curved axes.

The native `Cốt thép móng băng` command works with selected `WallFoundation` elements attached to straight walls. It extracts the top and bottom horizontal face boundaries and places two-way reinforcement layers using independent bar types and spacing in both directions.

KStruct packages the four U-Boot family files and the catalog JSON under `Resources/SlabModules/UBoot`. Run `Nạp family U-Boot KStruct`, then use `Bố trí module sàn` to place the loaded family type on selected floors. The package does not call the BimSpeed loader or read from the BimSpeed installation folder at runtime.

The native `Căn dầm theo sàn` command aligns selected horizontal straight beams to the nearest selected floor at the beam midpoint. It supports either beam top to slab underside or beam bottom to slab top, with an entered vertical gap and a confirmation preview before moving elements.

The native `Tạo hình Bubble slab` command previews a proposed grid of managed spherical DirectShape bodies within selected horizontal floors, keeps the configured top/bottom cover, excludes floor edges/openings and nearby structural supports, and creates or updates one managed shape per floor. It does not cut openings from the original Floor.

The native `Thép sàn Bubble` command uses the two-way slab bar settings for floors with managed KStruct Bubble geometry. Slab bars are automatically interrupted where their elevation intersects a Bubble sphere's bounding region; bars above or below the sphere region continue across the floor.

The native `Thép sàn U-Boot` command finds U-Boot family instances on one selected floor, then opens the standard two-way slab reinforcement settings with those module instances selected for automatic bounding-box exclusions at each bar elevation.

Straight-beam reinforcement also supports optional second longitudinal rows at the top and bottom with independent counts, independent RebarBarTypes, and a shared clear spacing. The rows run the supported beam length and are rejected when they collide with the tie cage or other longitudinal rows. Excel/CSV accepts `TopLayer2Count`, `TopLayer2TypeName`, `BottomLayer2Count`, `BottomLayer2TypeName`, and `LongitudinalLayerSpacingMm`; old configuration files leave these rows off.

Native KStruct reinforcement commands now try Revit's shape-driven Rebar creation first and fall back to Revit FreeForm Rebar for unsupported standard bars without hook types. This keeps the centerline geometry available without loading optional BimSpeed RebarShape RFA assets. FreeForm bars have no shape-driven editing handles; shape matching for hooked bars and StirrupTie reinforcement still depends on Revit accepting the requested geometry and hook/style configuration.

The native `Thép chân chó sàn` command replaces `ThepChanChoRebarCmd` for horizontal planar Floors. It creates independent six-segment Rebar chairs between slab mats, with selectable bar type, orientation, cover, upper-mat diameter, support span/feet, and X/Y spacing. Placement is clipped against tessellated slab boundaries and openings. `Bố trí module sàn` places an already-loaded, supported family type on a spacing grid inside selected horizontal planar Floors using Revit API; it measures the rotated family-type bounding box, keeps that footprint inside slab edges/openings, rejects overlapping grid spacing, treats entered spacing as a maximum center-to-center interval, and excludes points whose bounding-box footprint overlaps structural-column or KStruct drop-panel bounding boxes or violates a user-entered clearance. This remains a geometric approximation, not a product-specific Bubble/Mushroom/U-Boot layout rule; KStruct does not supply vendor family assets. Both commands need validation in a Revit project.

KStruct module placements now carry a KStruct-owned Extensible Storage tag with their host Floor ID. The placement dialog can update the selected floors by replacing only previously KStruct-tagged instances; each floor update is transactional, and a floor keeps its previous modules if the new layout cannot place any. `Xóa module sàn KStruct đã tạo` removes only tagged KStruct instances on the selected floors after confirmation. Family content must already exist in the Revit project; this workflow does not load BimSpeed or vendor libraries.

The native `Xóa hồ sơ móng đã tạo` command replaces the foundation `DeleteAllCreatedViewsCmd` workflow for KStruct-generated isolated/strip footing drawing sheets. It identifies sheets by KStruct sheet/name prefixes, includes placed section views, and asks before deleting the selected sheets/views and their dependent viewports. It does not remove unrelated project views.

The isolated-footing reinforcement dialog now supports named presets: save, load, delete, import, and export XML profiles containing bar types, covers, spacing, enabled mats/edge bars/column dowels, hook types, and hook lengths. Profiles live under `%APPDATA%\KStruct\FootingRebarProfiles.xml`; imported type names must exist in the active Revit project before the preset can be applied.

The native `PreviewBeamRebarSplicesCommand` replaces the BimSpeed `BeamRebarSplicePreviewCmd` preview for selected beam-hosted or directly selected Rebar. It computes each position's developed length from all bounded centerline curves, stock-length segment counts and lap intervals, optionally alternating splice phase by bar group, and can export the preview table to CSV. It is read-only and does not cut or regenerate Rebar. For hooked/bent bars, stations are distances along the developed centerline; the geometry is marked for review because the preview does not enforce code-required straight splice zones or design checks.

The native `Tạo drop panel mushroom` command creates a thicker structural Floor patch around selected columns, aligns its top to the selected horizontal slab, verifies the panel stays inside the slab loops/openings, and joins it so the panel cuts the overlapping base slab. It requires a project FloorType thicker than the base slab. `Thép drop panel Mushroom` creates separate X/Y bottom and top bar mats on KStruct drop panels, applies side/bottom/top covers and spacing, and clips bars to tessellated panel loops while excluding the linked column footprint. Its optional U-bar mode creates two-way vertical U-shaped Rebar around the linked column with a selected RebarBarType and maximum spacing; the lower crossbars are vertically offset to keep the two directions apart. It replaces only Rebars tagged by KStruct on that panel. The command lays out Rebar geometry and does not calculate punching capacity or verify a structural design.

The native `Review module sàn` command provides a read-only geometric/host audit for selected or slab-hosted family modules and KStruct drop panels. For each module it reports family/type, Level, plan location, center and bounding-box footprint against slab edges/openings, approximate 3D bounding-box overlaps with the other reviewed modules, host and elevation. For drop panels it reports whether they are joined at the slab top, the ElementId/type of the linked column, and hosted Rebar element counts by bar type with KStruct-owned and other bars separated. KStruct-owned drop-panel bars are also grouped by BOT_X/BOT_Y/TOP_X/TOP_Y partition so missing mats are visible; it can export the report to CSV. Bounding-box overlap/footprint checks are geometric approximations; this is not a structural design check and does not recreate proprietary Bubble/Mushroom/U-Boot review calculations.

The native `Xuất mô hình phân tích CSV` command exports Revit Analytical Members, Panels and Openings with element IDs, node IDs, explicit NODE rows with coordinates in millimeters, analytical role, AnalyzeAs, material/section names, member rotation, panel thickness and panel-opening links. Member endpoints use Revit analytical ReferencePoint IDs where exposed; connected reference points may be matched to panel/load geometry within 1 mm. Unconnected analytical reference points stay separate. Remaining geometry-only nodes are coordinate clusters at 1 mm and are flagged as such; inspect the exported node statuses before analysis. The command also exports Area/Line/Point Loads with force/moment vectors converted to kN-based SI units, all Load Cases (including those without load instances), host/workplane IDs, Boundary Conditions geometry class/local axes, and Load Combination components with factors. Curved geometry is tessellated and flagged. This remains an exchange CSV, not an ETABS `.e2k` file; it does not map ETABS section/material IDs or export each support restraint DOF, so support behavior still requires review.

The native `Tối ưu Analytical Member` command implements the beam-end-to-column-axis adjustment workflow with a user-set search distance (default 300 mm), independent minimum member length (default 200 mm), and selected-only or full-document scope. It only adjusts straight analytical Beam/Girder members near vertical Analytical Columns that have physical associations and bounding boxes. It previews the change count and warns that Revit `SetCurve` can disconnect analytical node relationships at moved ends. Review connectivity after applying; curved members and columns without an associated physical element are skipped.

The native `Tối ưu Analytical Panel` command brings horizontal Analytical Floor Panel outer edges toward nearby parallel straight analytical Beam/Girder axes (default search distance 200 mm), with selected-only or full-document scope. It retains existing Analytical Opening contours and rejects a panel if any opening would lie outside or too close to the adjusted boundary. Only horizontal panels with straight outer edges are supported; panel contour edits should be reviewed for analytical connectivity after applying.

The native `Căn Analytical Node` command replaces the Design/Coordinates workflow for Revit analytical `ReferencePoint` nodes. Select X/Y/Z, set a tolerance in meters, choose origin nodes, edit each target coordinate, then pick import nodes and review their nearest origin/distance/status before applying. Only unambiguous matches inside tolerance are enabled by default; the review table can exclude individual nodes. The command moves only the chosen axis and leaves the other two coordinates unchanged. It does not modify project Shared Coordinates. Inspect the connected Analytical Members/Panels after moving nodes and save a backup before applying.

Three native commands create Analytical Panels from planar face loops, closed loops of bounded Analytical Member curves, or ordered Analytical Node points. Each command assigns Floor, Panel, or Wall Structural Role; a horizontal/vertical face determines geometry orientation independently of that role. Face and member-curve loop sets can create nested Analytical Openings. Member-curve creation requires endpoint-connected degree-two loops and rejects branches; self-intersections and other invalid boundaries remain subject to Revit analytical boundary validation. Point-based creation requires at least four nodes in the intended perimeter order. All loops must be planar and pass Revit analytical boundary validation. These are analytical model elements, not physical Floors.

The native stair reinforcement dialog now allows independent bottom/top/side covers and separate start/end RebarHookType choices for longitudinal and distribution bars on straight stair runs and landings. Default hook selections remain empty; this extends the existing native stair workflow while keeping its Revit API-only dependency set.

The native `Sao chép tường sang Level` command covers the wall-module copy-to-level workflow for straight vertical Basic Walls without inserts. It creates new walls at selected Levels and preserves type, height, base offset, structural flag, Mark, and Comments; where a matching upper Level exists, it also preserves the top constraint and offset. Walls containing doors, openings, embedded walls, or other inserts are skipped rather than copied with broken host relationships.

## Column ribbon status

The `COLUMN REBAR V3` panel now has the native `Cốt thép cột & triển khai V3` command and a native plan-dimension command for columns, beams, and foundations. The former login-gated full-rebar and selected-column buttons have been removed. Column drawing creation is handled by V3 deployment settings. The `Cập nhật bản vẽ` button now invokes the native KStruct updater. V3 saves the selected rebar configuration as Extensible Storage on each generated column.

The old `BimSpeedStructureColumnDesignPort` project is excluded from the KStruct build and solution. Existing V3 columns created before configuration storage was added must be regenerated once with native V3 before the native update command can rebuild their drawings.

KStruct targets the Revit 2024 API directly. Its build output contains only `KStruct.dll` and `KStruct.pdb`; no BimSpeed, Newtonsoft.Json, MahApps.Metro, or CommunityToolkit assemblies are required.

## Build

Open `KStruct.sln` in Visual Studio with the .NET Framework 4.8 targeting pack.

    .\Build-Debug.ps1

Build Debug writes to `D:\SDK_HD\KStruct\bin\Debug`. The Revit 2024 manifest loads KStruct from that folder. Close Revit before building because it locks the loaded assemblies. The script also checks the built assembly references and output folder, and fails if a BimSpeed assembly is referenced or copied beside KStruct.

The native footing drawing command now creates top- and bottom-layer plan views plus two perpendicular section views on a sheet per selected Structural Foundation family instance with LocationPoint. KStruct-created footing mats use layer-specific Partitions to separate TOP and BOT plans; older or non-KStruct Rebar remains visible if its layer is not identified. The sheet uses native model Rebar and does not require BimSpeed's two-layer footing detail family.

The native isolated-footing reinforcement command includes optional closed horizontal StirrupTie loops (O) and open three-segment C bars around the footing side faces. Both use a configurable layer quantity distributed evenly through the covered footing depth and saved in presets; C bars expose independent end-return toggles and lengths for X- and Y-aligned sides. The O loops use the selected X-direction RebarBarType, optionally accept a RebarHookType, and require a matching StirrupTie RebarShape in the project. C bars use native Rebar geometry. Both options require the largest planar top face to cover at least 99.5% of the footing footprint bounding box. These port the BimSpeed C/O layouts geometrically; BimSpeed horizontal-hook shape behavior and exact array offsets still require Revit review; footing capacity checks remain outside the command.

The native footing reinforcement command now also accepts near-rectangular pile-cap instances for its user-configured orthogonal mats; this supersedes the earlier “no pile caps” scope note above. It validates that the largest horizontal top face covers at least 90% of the footprint bounding box; round, triangular, stepped and irregular caps are rejected. This only lays out the entered bar mats and optional edge bars/column dowels: pile-head anchorage, strut-and-tie detailing, and structural capacity checks remain outside the command.

## Revit review

Build success confirms compilation only. Review V3 column geometry, saved configuration, drawing regeneration, round columns, beam/floor connections, lap/starter settings, plan dimensions to grids, and Undo in a copy of a Revit project. Structural detailing still requires review by a structural engineer before issue.

## Native KStruct replacements

The former `BimSpeed Suite` dynamic command loader has been removed. Curved-beam and retaining-wall reinforcement now invoke native KStruct commands registered from the KStruct assembly, and both section-reference actions are in `KStruct Hồ sơ`. The `COLUMN REBAR V3` panel no longer contains a ColumnDesign port command.

`Khớp thuộc tính Rebar` applies the Geometry-group parameters, bar type, Partition, and hooks from a selected source Rebar to selected Rebars. It can either keep only targets with the same RebarShape or change shape-driven targets to the source RebarShape using Revit's `SetRebarShapeId`, which preserves the target geometry as closely as Revit can. FreeForm bars cannot be used as a source or target. An opt-in mode copies all compatible writable instance parameters, including Schedule Mark; review target geometry after using either shape-changing or full parameter-copy mode.
 The native distributed Rebar tag command places selected bars' tags along a chosen side of their extents, with paper-based offset and spacing; it skips bars already tagged in the active view and rolls back an individual failed tag. The native Rebar filter selects or temporarily isolates project Rebar by diameter, Partition, shape, host mark, Rebar style, reinforcement number and host category, with a reset-isolate action.

Current coverage exports load-case patterns, uniform AreaLoads oriented to Project/global axes, linear-additive or envelope load combinations, and LineLoads/PointLoads oriented to Project/global when their geometry maps uniquely to a single ETABS frame. ETABS self-weight multipliers are set to zero to avoid double-counting explicit Revit loads. Nonuniform AreaLoads, AreaLoads in work-plane/host-local axes, line loads spanning multiple or nonmatching frame segments, and point loads not uniquely located on a frame are reported as skipped. Point BoundaryConditions with Project axes are mapped to a coincident ETABS joint: fixed/released DOFs become restraints and uncoupled springs map through CSI PointObj.SetSpring. Revit translational spring moduli convert to kN/m; rotational moduli convert from kN-m/degree to kN-m/radian. HostLocal orientations, unmatched/ambiguous coordinates, line/area supports, and coupled connection DOFs remain unsupported. Curved analytical members are segmented from tessellated geometry.
