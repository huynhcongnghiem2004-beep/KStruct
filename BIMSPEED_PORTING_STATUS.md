## Known parity gaps requiring implementation or runtime review

- **Bend Rebar** (`BimSpeedRebar.EditRebar.EditRebarCmd`, tooltip “Bend Rebar”): the native jog command lets the user choose a straight segment in a planar Standard Rebar path, replace that span with an offset jog, retain the other curves and end hook types/orientations, and restore common shape-driven set layouts plus excluded positions. It also updates a single unconstrained planar FreeForm bar in place through `RebarFreeFormAccessor.SetCurves`, retaining the element and host. FreeForm sets, constrained FreeForm, and non-planar forms remain unsupported. Runtime validation remains open.
- **Wall Rebar preview** (`WallRebarVnCmd`): `ReinforceStraightWallCommand` now creates a 2D elevation preview from the exact Rebar centerlines inside a temporary transaction, rolls that transaction back, and asks for confirmation before creating the final Rebar. The preview and cancel/commit behavior still need runtime validation in Revit.
- **Column rebar / deployment parity (open)**: source inspection of the installed BimSpeed column module shows distinct rectangle layouts for outside/inside bars and optional additional diameter, editable main and additional stirrup types/spacing and custom cross-tie geometry, separate per-column saved layouts, selective transfer of main-bar/stirrup settings between levels, framing/floor/manual splice selection, top hooks and splice positioning, quantity/partition metadata, and detailed view/tag/dimension/schedule settings. KStruct V3 implements a substantial native subset, but does not yet expose all of these options; specifically its supplementary-bar UI is disabled and its beam/floor association is not connected. The V3 editor now loads a valid saved per-column configuration. The standalone drawing commands now use the detailed V3 sheet builder and require existing KStruct V3 rebar plus saved project deployment settings. A source compile check passed in an isolated directory; the normal `Build-Debug.ps1` remains pending because Revit currently holds `bin\Debug\KStruct.dll`. Do not call the column module fully ported until the remaining layout/connection settings are implemented and reviewed in Revit.
- **Rebar Opening** (`BimSpeedRebar.RebarOpening.RebarOpeningCmd`): `ReinforceFloorOpeningCommand` creates four trimmer bars for rectangular openings in horizontal Floors and two face layers around rectangular openings in straight vertical Walls. It now reads `Opening.BoundaryCurves` for polygonal openings and generates edge bars for every tessellated segment; reruns replace only bars tagged to the same opening and host. Nonvertical walls remain unsupported, and curved boundaries use a straight-segment approximation; validate clearances, segment count and bar placement in a Revit model.
- **Slab Rebar Classic / Plans**: `ReinforceSlabRegionCommand` adds named polygonal regions with user-selected top/bottom layer, local X/Y direction, bar type and spacing, clipped against the horizontal floor face and its openings; reruns replace only the KStruct bars with the same floor and region name. It rejects self-intersecting boundaries and uses scanline clipping, with endpoint cover inset along each generated bar. `MarkSlabRebarAdditionalCommand` lets the user classify selected manually drawn floor-hosted Rebar for the additional plan. Sheet creation separates host-floor bars above/below the slab midplane and marked bars for reinforcement plans. Vendor-specific cap shapes/freeform boundaries are not reproduced; runtime validation is open.
- **Slab Rebar Tag**: `TagSlabRebarSetsCommand` places one selected Rebar Tag per multi-position slab Rebar set and draws a view-specific line across the set's shorter plan extent. Tag family label formatting and line placement still depend on the project's Rebar Tag family and should be checked in a real plan view.
- **Create Lintel** (`HTConstruction.Addin.Commands.CreateLanhToCmd`): the native KStruct command selects a Structural Framing type and creates or updates a tagged lintel above selected doors/windows hosted by straight horizontal walls. A vertical centerline offset is configurable. Other opening families, wall openings without a Door/Window instance, and curved/stacked hosts are not covered yet; placement needs review in a Revit model.
- **Remaining structural general tools**: `QuickStructuralModelCommand` covers columns, beams, rectangular floors, basic straight walls and footings under selected point columns, but does not reproduce unverified QuickModel-specific options; it preserves the older dedicated draw commands as well. Floors are world-axis rectangles, walls use an entered height, and the footing command uses the selected level. `CreateLeanConcreteCommand` requires a horizontal planar bottom face and creates the lean concrete with the exact footing footprint (no overhang); verify Floor Type thickness, level offset and intersection behavior in a representative foundation model. `CheckStructuralTypeNamesCommand` uses a transparent naming heuristic (whole-mm width × height in either order and the full normalized material name); review the CSV because project naming abbreviations and custom family parameters may need project-specific rules. `AlignStructuralElementsToGridCommand` translates columns, beams, and walls to a straight Grid without rotating or resizing them; review intended anchor points on representative models. `DimensionSelectedGridsCommand` covers selected straight parallel grids in plan views. `DimensionSelectedLevelsCommand` requires an upright section/elevation. `ExportPileCoordinatesCommand` exports selected Structural Foundation center points to project and internal coordinate columns; confirm its survey coordinate convention against a site control point before field use.
- **Beam shop drawing cut workflow** (`BeamRebarCutShopCmd`): KStruct has four review tabs for individual bar-position demand (including shape/geometry), QC-qualified stock, cut patterns, and excluded/problem bars. Demand can filter longitudinal bars and stirrups by `RebarShape.RebarStyle`; unclassified bars have a separate option. Blank length can use Revit length or CAD straight-leg length (arcs converted to tangent legs), with the selected method, Revit length, centerline length, delta, and geometry warnings shown in review and CSV. Geometry checks cover missing shapes, near-zero/discontinuous segments, and bend radii. Stock receipt records type, diameter, length, quantity, warehouse/bin, receipt reference and UTC timestamp; QC pass/reject records inspector and UTC time, and only Available + QC passed stock is used. The plan CSV records source/location, asks for explicit scope confirmation for exclusions and geometry warnings, decrements inventory on issue, and returns reusable offcuts to pending QC. Full Revit validation and any remaining BimSpeed-specific receiving/QC rules remain open.
- **Quantity and site tools**: KStruct now has a multi-category element report with dynamic instance/type parameters, an XLSX or CSV detail file, and a category/family/type quantity summary CSV. The report remains available as XLSX/CSV and now optionally creates or updates a native Revit category schedule in the project. Schedule creation depends on the fields Revit exposes for that category. Formwork binds and updates its own `KStruct_FormworkArea` shared parameter and exports geometry totals to CSV after confirmation. Excavation creates and updates a DirectShape pit around selected foundation bounding boxes; the user can configure batter as a horizontal/vertical ratio, built as a loft from three sections. It represents a coordination volume and does not cut terrain or follow terrain surfaces. Split Zone creates/updates named box volumes, assigns `KStruct_Zone` to intersecting model elements, and can copy intersecting elements from one Revit Link into selected zones with KStruct-owned copies replaced on rerun. It copies whole elements (so elements crossing several zones may be duplicated), supports persisted category filtering, and can copy writable same-name instance parameters with matching storage/spec types. Each zone replaces old copies only after all selected source elements copy successfully; failed zones retain their old copies. Configurable source-to-destination instance and type parameter mapping is available by category; mapped type parameters are written to a new destination type assigned only to that copy, avoiding edits to existing KStruct elements. ElementId parameters and geometric splitting remain unsupported. None of these workflows has been checked against a sample model; formwork face inclusion, openings, connected solids, generated bottom formwork, and linked copy/host behavior need engineering/runtime review. The picked-face area query replaces only `GetAreaByPickFace`.
- The KStruct commands listed above have source-level coverage and build coverage only. Their Revit UI behavior and resulting model geometry still require validation with representative projects before BimSpeed can be removed.

## Build/dependency gate

Build with `Build-Debug.ps1` in `D:\SDK_HD\KStruct`. The script verifies the compiled KStruct assembly has no BimSpeed assembly references and that the output directory contains no copied BimSpeed DLLs. This does not prove runtime parity; the known gaps above remain open.

Latest build: **passed** with 0 warnings and 0 errors. The Debug output currently contains only `KStruct.dll`; `KStruct.csproj` references Revit API and framework/WPF assemblies, with no BimSpeed or third-party runtime DLL references. This establishes that KStruct itself does not load BimSpeed binaries, but it does not mean every BimSpeed feature has reached parity or has been validated in Revit. Keep BimSpeed installed until the remaining feature gaps and representative-project runtime checks are complete.
